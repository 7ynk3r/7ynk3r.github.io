The output was never the product. Every answer I get from a model is stale within weeks. The thing I actually keep is the request, which grew from one sentence into a page after enough bad answers.

An output is one run of a sampling process that won't repeat. A spec can be versioned, diffed, reviewed by someone who wasn't there, and handed to a different model next year. Once I saw that, bad outputs changed meaning. They stopped being failed deliveries and became test cases: each one points at the exact sentence my spec was missing. Frustration is just that requirement arriving before I can name it.

Past a certain size the spec becomes a harness: rules for context, tool routing, memory, and evals. That's where judgment lives, and it changes the economics. A cheap model can't infer much, but inside a tight harness the rules have already done the inferring, so it beats a frontier model running loose on repeat work.

The hardest version of the claim: if a dozen bad outputs still haven't taught me how to write the spec, the model isn't what's missing. I don't know what I want yet.
